# WSPORT

## Обзор проекта
- **Название**: WSPORT (бренд на экране входа обновлён с «ФОРМА» на «WSPORT»)
- **Цель**: фитнес-сайт с расчётом нормы КБЖУ, подбором рецептов и упражнениями для зала
- **Стек**: чистый HTML/CSS/vanilla JS SPA, статика на Cloudflare Pages (worker `47733657-aa80-42b6-861e-c5b1d3a78291`)

## Что сделано в этой сессии
1. **Экран входа**: название заменено на «WSPORT»; текст «Аккаунт хранится только в этом браузере…» заменён на короткое, аккуратное описание сайта.
2. **Расчёт КБЖУ**: `calcNorm()` в `app.js` использует формулу Миффлина-Сан Жеора (BMR) и рекомендации ISSN Position Stand по белку (1.6–2.2 г/кг) и жирам (мин. 0.6 г/кг) — с комментариями в коде, объясняющими научное обоснование.
3. **Анимация подсветки БЖУ**: `.macro`/`macropop` в `styles.css` смягчена — длительность увеличена с 0.42s до 1.1s, ослаблен scale, добавлен плавный box-shadow переход вместо резкого мигания.
4. **Фото рецептов**: все 48 рецептов (36 ранее без фото + 12 уже имевших) теперь содержат `img` в `data.js`, файлы лежат в `public/static/img/food/`.
5. **Кнопка «Другой вариант»** удалена — она дублировала функцию «Собрать день».
6. **Анимация в разделе рецептов**: добавлен shimmer-блик по фото карточки при наведении (`.rphoto::before` + `@keyframes rshine`) и лёгкое появление бейджа калорий (`@keyframes rtagpop`), чтобы раздел не выглядел пустым.
7. **Бренд WSPORT везде**: заменены остававшиеся упоминания «ФОРМА» — `<title>`, бренд онбординга, бренд в сайдбаре приложения, бренд в верхней панели (topbar).
8. **Toast-уведомления при входе/регистрации**: после успешного входа снизу экрана показывается «Успешный вход!», после успешной регистрации — «Успешная регистрация!» (использован уже существовавший в проекте компонент `#toast`, просто добавлены вызовы в нужных местах).
9. **Ручной ввод КБЖУ**: на вкладке «Норма КБЖУ» добавлен переключатель «Рассчитать по параметрам» / «Указать свои цифры». В режиме ручного ввода пользователь задаёт калории, белки и жиры сам (углеводы досчитываются автоматически по остатку калорий). Введённые значения проверяются и мягко корректируются:
   - калории ограничены диапазоном 800–6000 ккал;
   - белки — 20–400 г, жиры — 20–300 г;
   - если известен вес пользователя, белок дополнительно ограничен ~3 г/кг, жиры ~2 г/кг (ISSN-рекомендации);
   - если белки+жиры «съедают» больше 85% калорий, они пропорционально уменьшаются, чтобы осталось место для углеводов;
   - под полями выводится понятное объяснение, что и почему было скорректировано.
   Выбранный режим (авто/ручной) и введённые значения сохраняются в профиле пользователя (localStorage) при нажатии «Сохранить в профиль».
10. **Расширена база упражнений (зал)**: было 26, добавлено 19 новых — теперь **44 упражнения** во всех группах. Каждое новое упражнение содержит фото, целевые/вторичные мышцы (в т.ч. коды для анатомической SVG-схемы), рекомендованные подходы/повторы, шаги техники и частую ошибку — по той же схеме, что и старые записи.     - **Плечи** (3 → 5): + тяга штанги к подбородку, сведение на заднюю дельту в тренажёре

## Как пользоваться
1. Зарегистрироваться/войти на экране входа (WSPORT) — после успешного действия внизу экрана появится уведомление.
2. На вкладке «Норма КБЖУ» выбрать способ: рассчитать по параметрам (пол, цель, возраст, рост, вес, активность) или указать свои цифры калорий/БЖУ вручную — сервис проверит их на адекватность и подскажет, если что-то нужно скорректировать.
3. На вкладке рецептов выбрать «Готовый день» → «Собрать день» — меню подберётся под цель.
4. Каждый рецепт имеет фото, время готовки, калории и БЖУ.

## ИИ-ментор бесплатно (Puter.js)
- По умолчанию чат работает через **Puter.js** (`chatProvider: 'puter'` в `public/static/config.js`): без ключей, без сервера и без оплаты со стороны сайта. Посетитель один раз входит в бесплатный аккаунт Puter (всплывающее окно); если когда-нибудь исчерпает бесплатный лимит Puter — пополняет свой аккаунт сам.
- **Без отдельного входа**: при входе или регистрации на сайте (в том же нажатии) Puter сам создаёт гостевой аккаунт (`attempt_temp_user_creation`) — окно открывается на секунду и закрывается. Это один раз на устройство: токен хранится в браузере (`puter.auth.token.v2`), дальше чат работает сразу. Если человек уже был залогинен на сайте, подключение произойдёт при первом сообщении. Скрипт Puter подгружается заранее в фоне, пока ИИ не подключён.
- Запасной вариант: если браузер заблокировал окно — в чате кнопка «Подключить»; если в сети Puter запрещает гостевые аккаунты — кнопка «Войти в Puter» (обычный вход/регистрация).
- Системный промпт ментора тот же (`static/chatPrompt.mjs`). История, стриминг и оформление не изменились.
- Настройки чата (шестерёнка, «Бесплатно / Свой сервер / Свой ключ») **убраны** — посетитель ничего не настраивает. Режим задаёт только владелец в `static/config.js`; старые настройки из браузера игнорируются, поэтому статус «не подключён» больше не появляется.
- Код режима «Свой сервер» (`worker/index.js` + Anthropic) оставлен как запасной: чтобы включить, укажи `chatProvider: 'server'` и `chatEndpoint` в `config.js`.

## Обновление: КБЖУ + Сахар
- У каждого рецепта и коктейля есть поле `s` — сахар на порцию, г (`static/data.js`); у продуктов базы — 8-й элемент строки (`static/foods.js`).
- Сахар показывается рядом с Б/Ж/У/ккал: карточки рецептов, окно рецепта, «Готовый день» (у блюда и в итогах), поиск продуктов, выбор порции, штрих-код, распознавание по фото, ручной ввод (поле «Сахар, г»), строки дневника, заголовки приёмов пищи и сводка дня.
- Штрих-код и поиск OpenFoodFacts берут `nutriments.sugars_100g`; ИИ по фото возвращает `s` для каждого продукта. Если у товара нет данных о сахаре — пишется «—» / «нет данных», и в сводке отдельно считается «без данных: N».
- Ориентир в сводке: не больше 10% калорий нормы (рекомендация ВОЗ для добавленного сахара) = `норма ккал × 0,10 / 4` г. Если больше — плашка «Сахар» становится красной.

## ИИ сайта без входа и окон (Pollinations)
- `static/config.js`: `chatProvider: 'auto'`. Если вписан `aiKey` (публичный ключ приложения `pk_…` с enter.pollinations.ai) — ИИ-ментор и распознавание еды по фото работают сразу, без входа, окон и вкладок. Ключ сделан для сайтов: тратит только бесплатный дневной лимит владельца и ограничен по IP.
- `aiModels` / `aiVisionModels` — модели по очереди: если первая недоступна или лимит на неё кончился (402/429 и т. п.), берётся следующая.
- `window.siteAI` (в config.js) — общий запрос к OpenAI-совместимому API для чата (`chat.js`, стрим) и фото (`diary.js`, провайдер `site`).
- Пока ключа нет — работает запасной Puter (разовый вход через окно).

## ИИ сайта: ключ Pollinations (sk_) и выбор моделей
- Puter отключён (просит номер телефона США). `chatProvider: 'open'` — ментор и фото еды идут через Pollinations по ключу сайта; посетители никуда не входят.
- Ключ в `config.js` хранится как `enc:<base64 перевёрнутой строки>` (не открытым текстом). Ключ ограничен дешёвыми текстовыми моделями в кабинете Pollinations; бюджет — бесплатный лимит аккаунта.
- `aiPrefer` / `aiVisionPrefer` — модели по названию из кабинета (Gemini 3.8 Flash → GPT-5.4 Mini → DeepSeek V4.1 Flash → GPT-5.4 Nano). Сайт берёт точные id из `/v1/models` (кэш 12 ч), при 402/429/5xx переходит к следующей, неразрешённые (400/403/404) больше не пробует.
- История чата хранится по аккаунту WSPORT (на устройстве); общая история между устройствами появится вместе с базой данных.

## Фото еды: надёжность и экономия лимита
- Промпт: каждый продукт отдельно, вес по посуде (тарелка 24–26 см), способ приготовления, самопроверка kcal ≈ 4p+9f+4c.
- Очистка ответа ИИ (`VisionAI.clean`): числа вида «150 г»/«12,5», английские ключи, нет калорий → считаем из БЖУ, сахар ≤ углеводов, >9 ккал/г → значит посчитано на 100 г → пересчёт на порцию + подсказка «Проверь вес».
- Непонятный ответ → одна повторная попытка на следующей модели; зависание > 45 с → следующая модель; новое фото во время распознавания отменяет старый ответ.
- Распознанные блюда попадают в «Недавние» (база на 100 г) — повторно добавляются в пару нажатий.
- Экономия: фото уменьшается до 896 px, в чат уходят только последние 14 сообщений.
- Исправлен вылет окна «Добавить еду» за край экрана на телефоне после распознавания.

## Мобильная версия: аудит 320–430px (сентябрь 2026)
- Телефон: профиль — аватар с серией в верхней панели, ИИ-ментор — вкладка «Ментор» в нижнем меню. Плавающие кнопки убраны (закрывали «+» у приёмов пищи).
- Фото еды: кнопки «Камера» и «Из галереи»; распознавание стартует сразу после выбора фото, результат прокручивается в видимую зону.
- Исправлены вылеты за край экрана: окно еды после распознавания, поле штрих-кода на 320px, окно «Мой прогресс» (длинное название упражнения в списке), окно оценки рецепта, список веса и шапка профиля; верхняя панель на 320px.
- Названия продуктов в дневнике — до 2 строк вместо обрезки; бирка мышцы в упражнениях с «…»; «1 взвешивание» вместо «1 взвешиваний»; БЖУ на вкладке КБЖУ — в один ряд.
- Пока открыто окно, страница под ним не прокручивается; высота окон учитывает панель браузера iPhone (dvh); нижнее меню и шапка непрозрачные.

## Фото еды: точнее счёт (v3)
- ИИ сначала описывает, что видит («seen»: штуки, размер горок), затем даёт вес и КБЖУ **на 100 г** по опорной таблице домашних блюд в промпте; итог на порцию считает сайт (`VisionAI.clean`, поле `per100`). Старый формат (итог на порцию) тоже понимается.
- Ориентиры веса в промпте: доли тарелки, котлета 80–100 г, яйцо 55 г, кусок хлеба 25–30 г и т. д.; штучные продукты — один пункт «котлеты ×2».
- В результате: кнопки −/+ у веса (шаг 10/25 г) и у количества штук (вес одной штуки × N) — можно поправить «на глаз» без весов.

## Штрих-коды: поиск по нескольким базам + фото этикетки
Порядок поиска (`lookupBarcode`):
1. **Мои штрих-коды** (`MyBarcodes`, localStorage, до 600 шт.) — всё, что уже находили, распознали по этикетке или ввели вручную с кодом. Мгновенно и без интернета.
2. **OpenFoodFacts** (мировая база, в т.ч. Россия) — по всем вариантам кода (EAN-13, UPC-A с нулём и без, UPC-E → UPC-A). Если на упаковке КБЖУ только «на порцию» — пересчёт на 100 г.
3. **USDA FoodData Central** (товары США и импорт; для кодов 46/47/48 не спрашиваем). Ключ `usdaKey` в config.js, по умолчанию `DEMO_KEY` (лимит ~30 запросов/час с одного IP — это запасной источник).
4. **Поиск в интернете через ИИ с веб-поиском** (`WebBarcode`, модели из `aiSearchPrefer`, напр. «Google Gemini 2.5 Flash Lite Search»): ищет точный штрих-код на сайтах магазинов и каталогов, берёт КБЖУ на 100 г; ответ с другим штрих-кодом отбрасывается; в карточке помечено «найдено в интернете — сверь с упаковкой». Работает, только если модель с поиском разрешена ключу Pollinations.
5. Нигде нет (или есть без КБЖУ) → карточка «Сфоткать этикетку»: ИИ читает таблицу «Пищевая ценность» (`VisionAI.label`), товар сохраняется за штрих-кодом. Также «Ввести вручную» (тоже запоминается) и «Найти по названию».
Ограничение: «Мои штрих-коды» пока хранятся на устройстве; общая база для всех друзей появится вместе с сервером и базой данных.

Почему у FatSecret находится больше: у них своя закрытая база (данные производителей + товары, добавленные пользователями, отдельные базы по странам, включая Россию). Доступ к их штрих-кодам через API — только тариф Premier (Premier Free — по заявке для студентов/стартапов, но с американской базой; другие страны — платно), плюс нужен свой сервер (OAuth-секрет, белый список IP). Копировать их базу нельзя.

## Дневник: шапка и запись тренировки (v2)
- Шапка «Дневник» — только заголовок (убраны пояснение и кнопка «Сегодня»). Вернуться к сегодняшнему дню — нажать на дату над неделей («→ к сегодня»).
- Упражнение выбирается только из базы: 42 упражнения раздела «Зал» + ~36 популярных (`WO_EXTRA`) с синонимами. Живой поиск по началу слов («присе», «жим лёж»), подсветка совпадения, стрелки/Enter на компьютере. Нет в базе — «Такого упражнения нет», кнопка «Сохранить» неактивна.
- Подходы: строка «Подход N · повторы · вес · ✓ · ×». ✓ записывает упражнение и сразу открывает строку следующего подхода (копия). «+ Добавить подход», «Сохранить» — окно не закрывается, внизу «Следующее упражнение →».
- Одно упражнение за день = одна карточка с массивом подходов: повторный выбор того же упражнения продолжает карточку, дубли не создаются. Закрыл окно с несохранёнными подходами — они сохраняются автоматически.
- В дневнике подходы показаны по порядку: «1 · 10 × 50 кг», «2 · 10 × 50 кг», «3 · 8 × 50 кг».
